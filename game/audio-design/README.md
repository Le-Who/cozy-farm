# Runtime foley bank

The four `*-bank.txt` files record the current sound selection, direction, duration request and runtime gain. The bank uses generated ElevenLabs recordings, not oscillator replacements. `public/audio/bay-samples.json` is rebuilt by `python scripts/prepare-bay-audio.py`; only listed, available takes enter the runtime manifest. `public/audio/` must contain exactly those runtime takes: Vite copies all public files into the build, even when no manifest entry references them.

`retired-takes/` preserves 97 prepared MP3s that were still in `public/audio/` after being omitted from the current banks and manifest. They were moved byte-for-byte, not regenerated or approved for playback. Its `inventory.json` records each original path, SHA-256, size, source archive and any explicit kitchen-review rejection. All source/provider archives remain unchanged. Retired takes must stay outside `public/`; adding them to the runtime manifest to satisfy an inventory check would wrongly reactivate them. The current 164 runtime takes, cue mappings, gains, loop flags and revisions were not changed by this cleanup.

The historical November 9 review added two salt takes, alternate pear-cut and fish-turn takes, and sustained grill, preserves, honey and rolling textures. The first replacement honey texture was rejected because its level dropped sharply between sticky folds. Its pre-conditioning copy remains in `source-takes/kitchen.honey@2.mp3`; it is absent from the bank and shipped audio. The replacement accepted at that stage was `kitchen.honey@3`. That older `kitchen.*` bank was subsequently superseded by the current `cook.*` selection; its prepared copies are now in `retired-takes/`.

`source-takes/` preserves the prepared recordings as they existed before this review's conditioning, so the revised files can be rebuilt without spending provider credits. These are pre-conditioning runtime copies, not original provider responses. The existing bank and the first eight new responses had already been prepared before this archive was created. Future generation stores exact provider responses and SHA-256 provenance in `provider-takes/`; the accepted honey @3 response and metadata are recorded there. The new salt base take used `eleven_text_to_sound_v2`; the numbered alternatives used `eleven_text_to_sound_v3`. Generation is run only with `npm run audio:generate -- <id>...`; the generator obtains its credential from the existing local environment and logs only take IDs or sanitized error status.

Effects are trimmed using measured stereo energy, given short fades, gently filtered, levelled with a conservative sample peak ceiling and MP3 encoded. Sustained textures receive interpolated gain over 100 ms windows to retain their quiet body. The browser joins their ends with an 80 ms overlap, holds one native looping source per contact, and releases it in 60 ms when contact ends. Music samples retain their measured tuning and original preparation.

Scene groups decode only their actual gestures. Muted scenes and zero effects/master volume do not fetch their banks. A later real gesture uses the same lazy cache path after sound is enabled. Pending one-shots expire after 160 ms or scene cancellation; failed files and failed manifest requests back off for 30 seconds, then retry only on a later demanded action or scene entrance. Decoded samples are reused on revisits. No audio scheduler interval runs for contact textures. Scene-effect cleanup preserves an already scheduled 60 ms contact release, including repeated stop requests and a fresh contact of the same kind. Source completion or voice-budget eviction clears only the matching contact and detaches its callback. Visibility suspension still stops and disconnects all sources immediately, because the suspended audio clock cannot finish a release. These lifecycle changes do not alter the sound bank or cue mappings.

Verification: `node --test tests/bay-audio.test.ts tests/bay-sample-manifest.test.ts`, `npx tsc --noEmit`, and `python scripts/audit-bay-audio.py --check`. The manifest tests verify bank equality, file revisions, explicit kitchen-review exclusions and preservation of retired recordings and their sources. Run the same audit with `--directory dist/audio` after building to check the shipped paths and reject orphaned MP3s. The stereo audit reports decoded sample peaks and 10 ms energy-window onsets; these are asset measurements, not sound-card latency or a subjective listening verdict. Actual browser output is recorded after the shared compressor, through its MediaStream destination, in `output/playwright/foley-native-fish.webm`, `foley-native-pear.webm`, `foley-native-workshop.webm` and `foley-native-dough-cut.webm`. Native UI fixtures exercise salting, pan contact, turning, plating, two successful pear cuts, a successful worker cut from one dough piece to two, real rolling and stationary held-tool silence. The browser harness keeps both test tabs visible, so real background-tab visibility suspension is covered by the lifecycle code and unit simulation, not claimed as a native hidden-tab observation.

Home silently primes only `daybreak.shutters` and `harbour.berth` through the existing gated cache while its forecast is open. A successfully committed sleep consumes its dialog-close cue, so no generic `page.fold` overlays the morning or ferry arrival. Ordinary close, cancel and back keep their existing cues. An exceptionally slow first decode can still exceed the unchanged 160 ms event deadline; no late sound is forced after a scene change. No recordings, gains or music settings were changed.
