# Возврат к незавершённому авторскому рецепту

## Подтверждённая проблема

База: `91a2ffb` (912 тестов). В настоящем интерфейсе проверочной фермы: «Мои рецепты» → «Новый рецепт» → яблоко первой порцией → отсутствующая груша второй порцией. Ссылка вела к готовому дереву, но после возвращения в книгу выбранного яблока уже не было: новый рецепт открывался с двумя пустыми местами. Для воспроизведения не требовались сбор или готовка; сохранение оставалось побайтно прежним.

## Ограниченное изменение

Добавлено необязательное поле `recipeDraft`: основа (`preserves` или `tart`), два места по одной порции и активное место. Сохраняется только одна задумка, о замене при выборе другого состава прямо сказано в карточке. Пустой редактор, простое открытие книги и продолжение не создают пустое поле и не записывают старую ферму.

Черновик не содержит команд, наград, запасов, результата готовки или брони продуктов. Строгий reader принимает только известные ингредиенты/особенности, количество 1, два места и хотя бы один выбор. Лишние, неизвестные или неверные данные отклоняются по прежнему контракту `restoreFarm`; старое отсутствие поля остаётся допустимым.

«Продолжить задумку» только возвращает выбранные места в редактор. Наличие продуктов проверяется по текущей ферме; исчезнувший ингредиент остаётся выбранным, но недоступная готовка не запускается. «Сбросить задумку» удаляет только поле. Оба действия проверяют открытую книгу и текущий ключ состава, защищены от второго нажатия того же жеста. Успешное приготовление совпадающего состава завершает черновик; отказ и другой состав его сохраняют. Расход, результат и награды готовки не изменены.

## Реальный интерфейс

Проверка через CUA, обычный `main.ts`, локальный стенд 5224, синтетические сохранения создавались только явной кнопкой fixture. Существующая ферма не заменяется.

- Desktop: яблоко первой порцией → ссылка отсутствующей груши → возврат в книгу → двойной щелчок «Продолжить». Состав и второе активное место сохранились; повторный щелчок не выбрал другой ингредиент. После перезагрузки `restoreFarm` принимает сохранение, все поля кроме `recipeDraft` совпадают с исходной фермой: день 3, 18 монет, 0 работы, яблоко 1, груша 0, дерево не собрано.
- Затем отдельной обычной продажей использовано яблоко. Продажа дала 4 монеты и существующую награду цели 8: баланс стал 30, работа 1, яблоко 0. После перезагрузки независимый Enter на «Продолжить» сохранил выбор яблока, но готовка оставалась недоступной. Это изменение экономики вызвано явной продажей, не черновиком.
- Двойной щелчок «Сбросить» оставил книгу открытой, не открыл появившийся под ним другой рецепт. После перезагрузки черновика нет, состояние после продажи прежнее.
- Отдельный origin `localhost` с шириной iframe 390 и высотой 844: выбор яблока → назад → двойной сброс → чтение сохранения. `saveBytesUnchanged: true`, `recipeDraft: null`, `valid: true`: полный JSON вернулся к исходным байтам, день/монеты/работа/продукты не изменились. После этого для визуального осмотра заново выбран один ингредиент. Карточка, объяснение одной задумки и обе кнопки целиком помещаются по ширине 390 px; кнопки переносятся на отдельные строки.
- Новая 3D-готовка в этом пакете не проходилась. Совпадающее завершение/отказ/другой состав проверены доменными тестами. Здесь не заявляются аппаратная производительность или GPU-сбор ингредиентов.

Повторяемые исходники стенда: `game/tests/fixtures/recipe-draft.ts`, `game/tests/manual/recipe-draft.html`, `game/tests/manual/recipe-draft-mobile.html`. Fixture ограничен loopback:5224, отказывается заменять v2/v3, предоставляет явный read-only просмотр точного состояния.

## Совместимость: проверенная граница

Новая сборка читает старое сохранение без поля и сохраняет новый черновик после reload. Это **не** означает двустороннюю совместимость с прежним writer.

Для отдельной проверки исходники старого reader извлечены из неизменяемого `91a2ffb` через `git archive`. Его `restoreFarm` получает новое корректное сохранение с черновиком: принимает ферму, но возвращает её без неизвестного поля. Таким образом, свежая вкладка прежней сборки при последующей записи может потерять только задумку. Существующая проверка raw-save защищает уже открытую устаревшую вкладку от перезаписи чужих изменений, но не решает этот случай свежего старого reader. Новая миграция или запрет старого writer в этом ограниченном пакете не добавлялись.
