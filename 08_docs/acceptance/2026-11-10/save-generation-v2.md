# Однонаправленный перенос сохранений в отдельное поколение

Проверенный код: `348ead47c105cdfcb301c0a1ad16641ca4aec120`, после основного изменения `dfa09b1e7511209b8e03ec1bdd8833eba50d056c`. Основа — объединённая сборка дневника, питомника и парома. Последующий коммит отчёта не меняет код.

## Закрытый риск

Старая игра записывала `cozy-farm-island-v1` без знания питомника и экспедиций. Новая игра теперь пишет только `cozy-farm-island-v2`. Старый ключ не удаляется и не перезаписывается новой игрой. Поэтому старая вкладка или старый выпуск не могут затереть новый прогресс своим сохранением.

При переносе точные исходные байты, включая пробелы, сохраняются также в отдельном журнале `cozy-farm-island-v2-migration`. Изменение старой записи после переноса не меняет этот снимок. Внутренняя версия модели фермы остаётся 1; поколение ключа отделяет несовместимые выпуски.

## Порядок и восстановление после прерывания

- Любая существующая v2-запись имеет приоритет. Пустая, повреждённая или неизвестная запись блокирует сохранение; перехода к старой ферме вместо неё нет.
- При первом переносе валидируется старая ферма, затем записывается журнал `pending` с точным оригиналом и нормализованным начальным снимком, затем v2-запись, затем журнал `complete`.
- Игровые записи разрешаются только после успешного завершения всей последовательности. Ошибка записи оставляет игру временной и требует повторной загрузки.
- После прерывания `pending` повтор использует только замороженный снимок, а не изменившуюся старую вкладку. Если v2 уже существует, сохраняется именно она и завершается журнал.
- Завершённый журнал при отсутствии v2 означает повреждение/удаление: повторного импорта старого прогресса нет. Исходный снимок доступен для скачивания, автоматического сброса нет.
- Повреждённый журнал не исправляется молча. При этом валидная v2-ферма остаётся доступной во временном режиме, а не заменяется новой фермой.
- Новая ферма без старой записи тоже получает завершённый журнал. Поздняя запись старой вкладки не становится основанием для импорта.

Все инициализации и записи новой версии выполняются под одним Web Lock. Устаревшая новая вкладка после чужой записи блокируется защитным модулем. Значение действия сериализуется до ожидания блокировки, поэтому очередь не подменяет раннее действие поздним изменением объекта. При незавершённых записях установлен обработчик предупреждения перед закрытием страницы.

Если браузер не предоставляет Web Locks или отказывает в блокировке, небезопасной записи без блокировки нет: можно открыть доступную ферму временно, интерфейс сообщает о невозможности сохранения. Для обычной игры нужен браузер с Web Locks и безопасный контекст (HTTPS либо localhost).

## Правила выпуска и отката

1. При выпуске сохранять старый ключ, новый ключ и журнал. Не очищать данные сайта и не переносить новый JSON обратно в старый ключ.
2. Старый выпуск при откате увидит старый прогресс. Новые достижения остаются в v2 и вернутся при запуске новой версии. Изменения, сделанные затем в старой игре, автоматически не объединяются и не импортируются повторно.
3. Предпочтителен исправляющий выпуск вперёд. Если нужен откат с переносом прогресса, нужен отдельный совместимый конвертер и проверка, а не копирование записи старому коду.
4. Закрыть/обновить старые вкладки полезно, чтобы игрок не вёл две разные истории; целостность v2 теперь обеспечивается отдельным ключом, а не этой просьбой.
5. Очистка всех данных сайта, потеря браузерного профиля или удаление одновременно v2 и журнала уничтожают признаки предыдущего переноса. Восстановление из такого случая не обещается. Локальный снимок не заменяет внешнюю резервную копию. Принудительное завершение браузера также может прервать ещё не выполненную запись; предупреждение закрытия работает в пределах возможностей браузера.
