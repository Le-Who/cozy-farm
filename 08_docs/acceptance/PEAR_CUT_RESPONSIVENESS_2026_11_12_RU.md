# Отзывчивое разрезание груши, 12 ноября 2026

## Причина и изменение

Первый короткий надрез навсегда фиксировал угол и положение плоскости. В production `createHoneyPears.trace` короткий горизонтальный жест 28 px оставлял прогресс `0.3125`; после отпускания полный вертикальный проход 200 px по видимой груше оставлял **те же `0.3125`**, без разделения. Это не случайность RNG: новый жест не мог изменить ранее выбранную плоскость.

- После отпускания сохраняется прежний физический надрез. Следующий жест сначала независимо подтверждает направление по настоящему контакту с mesh.
- Продолжение того же надреза сохраняет накопленную работу. Достаточно длинный прямой жест под другим углом или со смещением выбирает новую плоскость вместо случайной старой.
- Тап, дрожание и ещё не распознанный жест не стирают работу и не дозавершают старый разрез. Последнее отдельно найдено независимым review и исправлено до интеграции.
- Свайп можно начать на рабочей тарелке немного вне видимого контура. Засчитывается только путь по фактической поверхности. Взятие ножа из держателя остаётся переносом, без разрезания плодов по дороге.
- Видимая борозда обновляется также при смене плоскости с тем же процентом, а не только при изменении количества обработанных участков.

Математика закрытых половинок, объём груши, требование обработать обе груши, мёд и списание запасов не упрощены. Новые звуки, записи или триггеры звука не добавлялись: существующий звук по-прежнему сопровождает реально продвинувшийся контакт ножа.

## Проверка

Из `game/`:

```sh
node --test tests/pear-cut-interaction.test.ts tests/knife-trace.test.ts tests/honey-cookery.test.ts tests/pear-cut.test.ts
npx tsc --noEmit
npm run build
git diff --check
```

40 targeted tests прошли. Тестовый seam соединяет настоящий Three.js raycast по геометрии, `createHoneyPears.trace`, `view.update` с физической деформацией борозды и `recordHoneyKnife`. Это не отдельная имитация определения попаданий.

Новые регрессии:

1. Короткий случайный надрез → полный поперечный повтор: red до изменения, green после.
2. Параллельный повтор со смещением выбирает новую линию.
3. Тап не стирает частичный разрез; продолжение старой линии сохраняет работу.
4. Один быстрый проход, три редких и 150 плотных событий, оба направления: результат одинаковый; соседняя груша не разрезана.
5. Почти полный старый разрез → короткое поперечное начало: red при первом варианте исправления, green после review. Незавершённый новый жест не завершает старую плоскость.

## Native QA: не пройдена

Попытка выполнена только на облачном desktop, в отдельном профиле Chromium. Пользовательские сохранения и ПК не использовались. Штатный запуск:

```sh
chromium --user-data-dir=/tmp/cozy-pear-native-20261112 --use-gl=angle --use-angle=swiftshader --no-first-run --new-window http://127.0.0.1:5231/tests/manual/honey-pour.html
```

Vite совмещённого стенда honey/cutting запущен из штатного Terminal. В его PATH не было `node`, поэтому использован полный путь существующего Node; настройки окружения и безопасности не менялись.

Браузер сначала показал `Aw, Snap! Error code: 9`, затем на успешно загруженном honey fixture показал восстановление «Браузер не смог запустить трёхмерную графику». DevTools явно запрещён политикой организации; запрет не обходился. После наблюдаемого постороннего изменения активного окна дальнейший ввод остановлен для координации.

Таким образом, настоящие mouse/touch-жесты в отрисованном canvas, движение половинок, визуальный отклик при каждом кадре, компактные viewport и аудио в этой попытке **не подтверждены**. Не применялись `--no-sandbox`, `--disable-gpu-sandbox`, unsafe-флаги, отключение проверок сертификатов или изменения security-настроек. Повторная native приёмка остаётся необходимой; зелёные вычислительные регрессии её не заменяют.
