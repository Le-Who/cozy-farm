# Диагностика покрытия и непрерывных звуков

`game/scripts/audit-audio-diagnostics.mjs` только читает локальные файлы. Он не генерирует, не обрабатывает и не заменяет записи, не меняет manifest, банки, игровые триггеры или сохранения и не обращается к провайдеру аудио. Его вывод не подтверждает ни субъективное качество, ни одобрение владельца.

## Запуск

Из каталога `game` после установки обычных зависимостей проекта:

```sh
node scripts/audit-audio-diagnostics.mjs
node scripts/audit-audio-diagnostics.mjs --ffmpeg /absolute/path/to/ffmpeg
node scripts/audit-audio-diagnostics.mjs --coverage-only
node --test tests/audio-diagnostics.test.ts
```

Полный запуск использует уже установленный `ffmpeg` из PATH или явно указанный исполняемый файл. Установки, загрузок и вызовов ElevenLabs нет. Декодер получает только локальные MP3 и протоколы `file,pipe`; результат PCM остаётся в памяти. `--root` задаёт каталог `game` другого локального checkout. JSON выводится в stdout; сохранение отчёта возможно обычным перенаправлением shell.

По умолчанию измеряются все takes с `loop: true`. `--coverage-only` явно возвращает `loopAnalysis: "not-requested"` и ноль измеренных loops; это не заключение об их исправности. Ошибки входных файлов, ревизий, формата и декодера завершают команду с кодом 1 без частичного успешного отчёта. Диагностические отметки сами по себе дают код 0: это список для проверки, а не автоматическая приёмка или команда удалить звук.

## Статические ссылки

TypeScript AST просматривается рекурсивно в `src/**/*.ts` и `src/**/*.tsx`. Комментарии и похожие подстроки не считаются ссылками. Для каждого cue указаны файл, строка и один из статусов:

- `exact-literal`: найден точный строковый литерал. Он может быть только элементом preload-списка, типом или недостижимой веткой; это ещё не доказательство реального воспроизведения.
- `dynamic-template`: найден потенциально подходящий шаблон, например `instrument.${id}`. Значение динамической части и достижимость не устанавливаются. Полностью вычисляемые ключи могут остаться нераспознанными.
- `none`: такой статической ссылки не найдено. Это кандидат на ручную проверку привязки, а не разрешение убрать или автоматически включить cue.

Отдельно отмечаются cue без заполненного русского описания в `audio-design/events-ru.txt`. SHA-256 manifest и измеренных takes позволяет сопоставить отчёт с конкретными входными файлами. Проверяется указанная в manifest ревизия каждого файла. Существующий `audit-bay-audio.py --check` по-прежнему нужен для равенства банков, manifest и поставляемых MP3 и для проверки пиков.

## Численные метрики loops

MP3 декодируется в стерео float PCM 44,1 kHz. В памяти повторяется текущий алгоритм `BayAudio.seamlessBuffer`: 80-ms линейное перекрытие концов, не более четверти короткого файла. При изменении runtime-алгоритма диагностическую модель нужно пересмотреть.

После перекрытия считаются последовательные 100-ms RMS-окна; последнее окно может быть короче. Мощность обоих каналов суммируется без сведения в моно, поэтому противофазный звук не исчезает из измерений.

- `spreadDb`: разница P95 и P5 уровней окон в dB с линейной интерполяцией процентилей. Отметка для проверки появляется при значении от 12 dB.
- `lowThresholdRms`: большее из 0,001 и 15% медианного RMS. Это численный порог, не порог слышимости.
- `longestLowRunMs`: длительность последовательных окон ниже этого порога, включая переход через стык. Участок не может быть длиннее одного цикла. Отметка появляется от 200 ms.

100-ms окна не выявляют все короткие щелчки, оттенок материала или неприятный спектр. Последнее короткое окно, положение границ окон и версия декодера могут влиять на числа. Это не LUFS, не звуковая карта и не браузерная запись после компрессора. Gain cue, сила жеста, общая громкость, overlap голосов и фактическая остановка контакта здесь не моделируются. Мягкое «дыхание» записи может быть намеренным; отметка не означает брак.

## Следующий ручной шаг

Прослушивать отдельно: «Помешивание варенья, текущий вариант 3», «Помешивание теста, текущий вариант 3», «Раскатка теста, текущая запись», затем остальные отмеченные takes. Для каждой записи показать 2–3 цикла и отпускание настоящего контакта, сохранив обычный игровой уровень. Не соединять разные варианты в безымянные A/B-компиляции.

Для невызываемых cue сначала сопоставить ранее подтверждённые владельцем записи с конкретными файлами. `acceptedTakes` в `kitchen-review.json` обозначает машинный отбор, а не пользовательское одобрение. Этот аудит ничего не включает, не исключает и не переоценивает автоматически; исходники и архив снятых takes сохраняются.
